# 계획: 손글씨 변환을 유료 모델로 주기적으로 다듬기

> **상태: 1~7단계 모두 구현 완료 (2026-11-03).**
> 이 문서는 AI 코딩 도구(Antigravity 등)가 읽고 단계별로 구현하도록 쓴 계획서다.
> 시작 전에 `AGENTS.md`를 먼저 읽는다. 단계를 끝낼 때마다 아래 체크 상자와 `AGENTS.md`를 갱신한다.

## 1. 목표

- 지금은 손글씨를 **무료 모델(Gemini Flash 무료 사용분)**로 **초벌** 변환한다(`worker/worker.js`의 `/ocr`, 앱의 `autoOcr`).
  빠르지만 흘림체를 잘못 읽어 **말이 안 되는 문장**이 자주 나온다.
- 하루 한 번(또는 정해진 시각) **유료 모델이 원래 손글씨 그림을 다시 보고**, 초벌 글자를 문맥에 맞게 고쳐 **최신화**한다.
  - 잘못 읽은 글자를 다시 판독한다. 예: "엄무회의" → "업무회의"
  - 문맥상 말이 되게 다듬되 **내용을 지어내지 않는다.**
  - 요약·할 일·결정 사항도 다시 뽑는다. 달력 한 줄 요약, 할 일 모아보기, 구글 Tasks가 함께 바뀐다.
- **사용자가 직접 고친 글은 덮어쓰지 않는다.**
- 비용 상한을 두고, 무슨 일을 했는지 기록을 남긴다.

## 2. 지금 구조에서 알아둘 점

- 하루 메모는 드라이브 `필기캘린더/YYYY-MM-DD.json`(v2, `pages` 탭 배열)에 있다. 손글씨 탭의 `ocr` 필드는 `text, summary, todos, decisions, done, at, sig`다.
- OCR 입력 그림은 지금 **앱(브라우저)에서 캔버스로 그려 PNG를 만든다**(`noteImage`). 서버에는 그림이 없다.
- 서버(Cloudflare Worker)는 사용자 드라이브에 접근하지 못한다. 구글 리프레시 토큰은 기기의 localStorage에만 있다.
- 드라이브 권한 `drive.file`은 **같은 OAuth 클라이언트가 만든 파일**만 볼 수 있다. 서버가 같은 클라이언트 ID로 받은 토큰을 쓰면 이 파일들을 읽고 쓸 수 있다.
- 할 일 ↔ 구글 Tasks 연결 키는 `hc:날짜:hash(탭id|글)`이다. 할 일 글이 바뀌면 다른 할 일로 취급되니 주의한다(아래 5단계).

## 3. 설계

### 3-1. 어디서 돌리나: Cloudflare Worker 예약 실행(Cron Trigger) 추천

| 후보 | 장점 | 단점 |
|---|---|---|
| **Cloudflare Worker Cron (추천)** | 비밀값이 이미 거기 있음, 로그가 비공개, 무료 | 무료 요금제는 호출당 CPU 시간이 짧음 → 그림 그리기 같은 무거운 계산 불가 |
| GitHub Actions 예약 실행 | 시간 제한 넉넉, Node로 자유롭게 | **공개 저장소라 실행 로그가 공개됨**, 메모 내용이 로그에 새면 안 됨 |
| 안티그래비티/PC에서 직접 예약 | 설정 쉬움 | PC가 켜져 있어야 함 |

→ **Worker Cron**으로 하고, 무거운 일(손글씨를 그림으로 그리기)은 **앱이 미리 해서 드라이브에 올려 두는** 구조로 한다.

### 3-2. 흐름

1. **앱(초벌 때)**: 무료 OCR을 할 때 쓴 PNG를 드라이브 `필기캘린더/ink/YYYY-MM-DD_탭id.png`에도 올린다. 손글씨가 바뀌면 다시 올린다.
   `ocr`에 `quality: 'draft'`, `model`, `imageId`(드라이브 파일 id), `sig`를 기록한다.
2. **서버 예약 실행(매일 03:00 KST)**
   1. 드라이브 목록에서 최근 N일 메모 중 `quality === 'draft'`이고, `sig`가 그림을 만들 때와 같고, 마지막 수정이 1시간 이상 지난 탭을 고른다(아직 쓰는 중인 것 제외).
   2. 탭마다 PNG + 초벌 글 + **문맥**을 유료 모델에 보낸다.
      - 문맥: 날짜, 그날 일정 제목들, 같은 날 다른 탭 글, **개인 용어집**(3-4)
   3. 결과를 `ocr`에 반영한다. 원래 초벌은 `ocr.draft`에 보관하고, `quality: 'refined'`, `refinedAt`, `refinedModel`, `changes`(바꾼 부분 목록)를 기록한다.
   4. 저장 직전에 드라이브 파일의 `modifiedTime`을 다시 확인한다. 읽은 뒤 바뀌었으면 이번에는 건너뛴다(사용자가 쓰는 중).
   5. `digests.json`(달력 요약)을 갱신하고, 실행 기록을 `refine-log.json`에 남긴다.
3. **앱**: 다음 동기화 때 다듬어진 글을 받는다. 화면에 **"AI 다듬음"** 표시를 하고, 초벌과 비교하거나 되돌릴 수 있게 한다.

### 3-3. 사용자가 고친 글 보호

- 앱의 원문 칸(`#ocr-text`)에서 사용자가 글을 고치면 `ocr.userEdited = true`로 둔다.
- 서버는 `userEdited`인 탭을 건너뛴다. 또는 사용자가 고친 부분을 "확정"으로 모델에 넘기고 나머지만 다듬는다(2차 목표).

### 3-4. 개인 용어집 (정확도를 크게 올림)

- 드라이브 `필기캘린더/glossary.json`: 사람 이름, 지명, 회사·업무 용어. 예: 김과장, 의왕, GIS, Q-R&D
- 채우는 방법
  - 네이버 일정 제목에서 자주 나오는 단어
  - 다듬기 결과에서 모델이 "고유명사"로 표시한 단어
  - 사용자가 직접 고친 단어
- 매 다듬기 요청에 넣어서 "이 단어들은 이 표기를 따른다"고 알려 준다.

### 3-5. 모델·비용

- 기본: **Gemini 유료 모델**(예: 2.5 Pro 급). 이미 쓰는 Gemini 키에 결제를 붙이면 된다.
  - 유료 사용분은 구글이 학습에 쓰지 않는 조건이다(무료 사용분과 다름). 구현 시 최신 약관을 확인한다.
- 설정은 Worker 환경 변수로 둔다: `REFINE_MODEL`, `REFINE_MAX_PAGES_PER_RUN`(기본 20), `REFINE_MONTHLY_BUDGET_USD`(기본 5), `REFINE_DAYS_BACK`(기본 14)
- 비용 추정은 **참고치**다(가격은 바뀔 수 있음). 손글씨 한 장 = 그림 약 1~2천 토큰 + 글 수백 토큰이면 장당 1센트 안팎, 하루 10장이면 한 달 몇 달러다.
- 응답의 토큰 수로 비용을 누적하고(`refine-log.json`), 월 예산을 넘으면 그달은 멈춘다.

### 3-6. 다듬기 요청(프롬프트) 초안

```
당신은 한국어 손글씨 메모를 판독·교정하는 편집자입니다.
[그림]은 태블릿에 손으로 쓴 메모이고, [초벌]은 다른 모델이 읽은 결과입니다.
1) 그림을 직접 다시 읽고, 초벌에서 잘못 읽은 글자를 고치세요.
2) 문맥상 말이 되게 다듬되, 그림에 없는 내용을 추가하거나 의미를 바꾸지 마세요.
3) 확신이 없는 부분은 [?]를 붙여 남기세요. 그림·도형은 [그림: 설명]으로 둡니다.
4) [용어집]의 표기를 우선 따르세요. 날짜·일정은 [문맥]을 참고만 하세요.
5) JSON으로 답하세요: text, summary, todos, decisions, changes[{from,to,reason}], properNouns[]
[날짜] … [그날 일정] … [같은 날 다른 메모] … [용어집] … [초벌] …
```

## 4. 단계별 작업 (안티그래비티에 한 단계씩 요청)

각 단계는 독립적으로 배포·확인할 수 있게 쪼갰다. 끝나면 체크하고 `AGENTS.md`를 갱신한다.

- [x] **1단계: 앱이 OCR 그림을 드라이브에 올리기**
  - `applyOcr` 성공 시 같은 PNG를 `ink/` 하위 폴더에 업로드(있으면 교체). `ocr.imageId`, `ocr.quality='draft'`, `ocr.model` 저장.
  - 원문 칸을 고치면 `ocr.userEdited = true`.
  - 확인: 가짜 드라이브로 업로드 호출과 필드를 확인하는 시험을 `tests/`에 추가.
- [x] **2단계: 서버가 드라이브에 접근할 수 있게**
  - 앱이 로그인할 때 받은 리프레시 토큰을 Worker에 등록한다(`POST /refine/register`, 주인 확인 후 **Cloudflare KV**에 암호화 저장).
  - `wrangler.toml`에 KV 바인딩과 `[triggers] crons = ["0 18 * * *"]`(= 03:00 KST)를 추가한다.
  - 확인: `/refine/status`가 "드라이브 접근 가능"을 돌려준다.
- [x] **3단계: 다듬기 작업(`scheduled` 핸들러)**
  - 대상 고르기 → PNG·초벌·문맥 → 유료 모델 → `ocr` 갱신(초벌은 `ocr.draft`에 보관) → `modifiedTime` 확인 후 저장 → `digests.json` 갱신 → `refine-log.json` 기록.
  - 수동 실행용 `POST /refine/run?dry=1`: 저장하지 않고 결과만 보여준다.
  - 확인: dry 실행으로 실제 메모 몇 장의 전후 비교.
- [x] **4단계: 앱에 표시**
  - 탭·원문 칸에 "AI 다듬음 · 날짜" 표시, [초벌 보기] / [되돌리기].
  - 메모 모아보기·할 일·주간 보기는 다듬은 글을 쓴다(지금 구조 그대로 자동 반영).
- [x] **5단계: 할 일·Tasks 충돌 정리**
  - 다듬기로 할 일 글이 바뀌면 Tasks 키가 바뀌어 "삭제 후 새로 만들기"가 된다.
  - 다듬기 결과에 `todoMap`(옛 할 일 → 새 할 일)을 받아 체크 상태를 옮기고, Tasks 작업은 **제목만 수정(PATCH)**해서 같은 작업을 유지한다.
  - 연결표(`gtasks.json`) 키를 옛 키에서 새 키로 옮긴다.
- [x] **6단계: 용어집**
  - `glossary.json` 생성·갱신, 다듬기 요청에 포함. 앱 ⚙에서 용어 보기·추가·삭제.
- [x] **7단계: 비용·안전장치 마무리**
  - 월 예산, 한 번에 처리할 최대 장수, 실패 시 재시도(다음 날), 기록 보기(⚙ → "AI 다듬기 기록").

## 5. 하지 않을 것 / 주의

- 메모 내용이나 토큰을 **공개 로그(GitHub Actions 등)에 남기지 않는다.**
- 리프레시 토큰은 KV에만, 저장소·로그에는 절대 남기지 않는다.
- 사용자가 고친 글(`userEdited`)과 키보드 메모(`kind: 'text'`)는 다듬지 않는다.
- 다듬기는 손글씨 원본(획)을 절대 바꾸지 않는다. `ocr` 필드만 바꾼다.

## 6. 안티그래비티에 줄 첫 요청 예시

```
이 저장소의 AGENTS.md와 docs/PLAN-ocr-refine.md를 읽고, 계획의 1단계만 구현해줘.
- 기존 동작을 깨지 말고, tests/smoke.mjs가 통과해야 해.
- 앱 파일을 바꾸면 sw.js CACHE와 index.html ?v= 버전을 올려.
- 끝나면 계획서의 1단계를 체크하고 AGENTS.md도 최신으로 고쳐서 main에 올려줘.
```
